Executive Summary

AreaCurrent StateImportant Details
Migration pathGORM AutoMigrate at service startup plus an RBAC seed SQL migration.The model list in main.go is the authoritative table inventory for the OLTP database.
Users and authorizationUsers now include status. RBAC tables store role names and gRPC method permissions.users.role remains a text role name and is not declared as a FK to roles.
Service/product commerceservices also backs products using category='product' and type='product'.Carts support service or product items through optional references to services.id.
OrdersOrders retain denormalized line-item snapshots in order_services.orders.user_id is indexed, but no explicit User relation is declared in the model.
Career dataCompany/job catalog, skill profiles, resumes, job carts, applications, and provider submissions are now first-class OLTP tables.Several workflow tables use composite unique indexes to prevent duplicate saved jobs and duplicate applications.
AI threadsThread and message persistence is owned by the user service.Messages cascade on thread deletion and store metadata_json as jsonb.
Removed from docsThe old patients table is not in the current AutoMigrate list.If it exists in a live database, it is legacy drift rather than a current service-owned model.

Operational Notes

AutoMigrate current

The service starts by auto-migrating all 24 models. For production, explicit migrations would make schema changes easier to review and roll back.

RBAC Seed active

migrations/20260602_seed_rbac.sql creates and seeds roles/permissions idempotently. Runtime seed code also ensures defaults exist.

Sensitive Fields careful

users.password, resume content fields, AI message content, and provider request/response summaries may contain sensitive user data.

BI Boundary watch

The OLTP schema currently includes career metric rollup tables. The separate BI database described in requirements is not reflected in this OLTP model list.
